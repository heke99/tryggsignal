# ADR-001 — One Supabase project per municipality

- Status: Accepted
- Date: 2026-09-07
- Masterplan: 4, 168, 171, 172

## Context

Municipalities are separate public authorities with their own legal responsibility for their case data. A shared production database would make one tenant's misconfiguration a cross-municipality incident, and would complicate exit, audit and data-processing agreements.

## Decision

Each municipality gets its own hosted Supabase project (data plane) in eu-north-1. A single control plane holds the tenant registry, domains, branding, deployment metadata and feature flags — never municipal case documents. `platform.tenant_deployments` binds a tenant to its project ref, URL, publishable key and a SecretProvider reference for privileged credentials.

## Consequences

Stronger isolation and a clean exit path, at the cost of fleet operations: schema rollout, migrations and health must be driven per data plane. The application code base stays single; only configuration differs.
