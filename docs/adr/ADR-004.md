# ADR-004 — RBAC + ABAC enforced by PostgreSQL RLS

- Status: Accepted
- Date: 2026-09-07
- Masterplan: 16, 17, 18, 19, 138

## Context

Authorization must survive a bug in the API layer, and the authority (nämnd) boundary is a legal boundary, not a UI convention.

## Decision

Roles and permissions live in `authz`; assignments carry a scope (TENANT/AUTHORITY/DEPARTMENT/UNIT/TEAM) plus denormalized authority/department/team ids. `authz.can(permission, resource)` returns allowed/policy_id/reason and is called directly from the RLS policy on `core.cases`, so the API and the database cannot drift apart. Two functions — `authz.current_user_id()` and `authz.is_external_user()` — are SECURITY DEFINER solely to break policy recursion on `identity.users`; they take no caller input, return only the caller's own identity, run with an empty search_path and are executable by `authenticated` only.

## Consequences

Tenant-scoped administrators deliberately get no standing content access: their assignments carry no authority id, so the authority-boundary check denies case reads. Policy changes require a rerun of `tests/rls/authorization_matrix.sql`.
