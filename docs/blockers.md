# Blockers

Updated 2026-09-07.

`BLOCKED` = internal technical dependency. `EXTERNAL_BLOCKED` = credential, license, vendor API
access, contract or external human decision that the agent cannot obtain. Never invent external
access to make a phase appear GREEN.

The synthetic rows were deleted, `tests/rls/authorization_matrix.sql` re-ran GREEN — now covering documents, search and uploads as well — and both Supabase advisors re-ran with zero WARN/ERROR. `docs/performance.md` records what the test found and how it must be run next time.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| B-02 | The proxy never ran in the production deployment. Every hostname fell through to the root page, which redirects to `/domain-not-found`, so the deployed platform app looked as if no domain was configured. | `apps/platform-web/proxy.ts` sat at the package root. Next.js only compiles the proxy when it sits beside the `app` directory, which in this app means `src/`. Nothing warns about this: the app builds and deploys normally. The file was moved to `apps/platform-web/src/proxy.ts`, the build now reports `ƒ Proxy (Middleware)`, and `tests/unit/proxy-placement.test.ts` fails if it is ever moved back.                                                                                                                                                                                                                                                                                                                                                                                            |
| B-03 | The worker could never have processed a single job. Queue names, the job envelope and the queue client were all written against a contract the database does not implement.                                 | Three separate drifts, none of which a build or a type check can see: the worker spelled queues `document-processing` while PGMQ has `document_processing`; `assertEnvelope` validated camelCase keys while `config.enqueue_job` writes snake_case, so every real job would have been rejected as malformed; and there was no PGMQ client, no runnable process and no consumer at all — ten queues filled by cron with nothing reading them. Fixed by aligning the names, replacing `assertEnvelope` with `parseEnvelope` against the real envelope, and adding `PgmqQueueClient`, the handler router and `main.ts`. `20260908090000_p10_worker_runtime.sql` adds the idempotency ledger, dead letters and the run log; `tests/integration/worker_runtime.sql` verifies all of it against the database. |
| B-04 | With the control plane configured, every hostname that is not a platform surface returned 500 instead of the refusal page.                                                                                  | The proxy read `platform.tenant_domains` through PostgREST, which does not expose the `platform` schema: `Invalid schema: platform`. Exposing the schema would have fixed the error and made it worse — the browser key would then reach `tenant_deployments`, which holds a key and a credential reference per municipality. Replaced with `public.resolve_tenant_host`, a SECURITY DEFINER function returning only the routing fields in one round trip. Found by `tests/e2e/control-plane.spec.ts`, which is the first test in the repository to run the proxy against a real control plane.                                                                                                                                                                                                         |

## Notes

- The P30 load test is what filled the disk. It ran on the same small project that
  carries the control plane, in one uninterrupted batch. It also found and led to
  the fix of a real RLS performance defect, which is recorded in
  `docs/performance.md` and in migration `20260907140000_p30_rls_performance.sql`.
- No production data has been copied anywhere. The only fixture in the control
  plane is the `demokommun` development tenant, whose domain is deliberately
  `PENDING` because no DNS or TLS verification has taken place.
- The masterplan's `vector` extension is intentionally not enabled: semantic
  search (P20) is not implemented, and masterplan 12 forbids enabling extensions
  without need.
